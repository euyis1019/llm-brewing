# 研究脉络：从论文一到 unsupervised-metrics

这份文档按时间记录 Brewing 的思路怎样变化、每一步留下了什么结论。数字的出处写在括号里，细节回到 `docs/logs/` 查。

## 一条主线

Brewing 关心答案在模型深度上何时形成。两种读法从两头夹住它：外部训练的线性 probe 读出答案，叫"外部可解码"；把这一层的状态交给模型自己剩下的层去解码（CSD / Patchscope）也能读出，叫"自身可解码"。前者总是先成立，中间那段层就是 brewing。

这条主线没变过。变的是三件事：在什么数据上看，用什么口径判，看到之后拿它做什么。

## 论文一：在受控代码任务上发现 brewing

- **数据**：6 类合成代码推理任务（值追踪、计算、条件、函数调用、循环、展开循环），每类 4,050 个样本，答案是单个数字。
- **方法**：逐层训练 probe，配合 CSD。probe 第一次读对的层叫 FPCL，两者都读对的第一层叫 FJC。
- **结论**：16 个模型上都存在这段间隔，按模型统计约占深度的四分之一到五分之二。之后结局分成四类：Resolved（保持正确）、Overprocessed（曾就绪后被改坏）、Misresolved（稳定地错）、Unresolved（没算完）。针对性干预为分类提供了因果支持，比如把 FJC 处的状态重新注入，救回了近一半的 Overprocessed 样本（据 `reference/roadmap/cc.md` 对论文的摘录）。

论文一留下的问题：任务是合成代码；probe 要用金标签另训；四类是逐层对错的事后归类。

## 7 月：离开代码

General Prefill 把同一套测量搬到 9 个公开 benchmark 上，在 Qwen3-4B-Base 和 Qwen3.5-9B-Base 上做确认性检验。两个模型都是先外部可解码、后自身可解码，间隔分别为 4 层（L18 到 L22）和 6 层（L13 到 L19），换答案后缀也不变。事先规定的单层状态互换没有通过因果判据：现象在观测上成立，因果上还没闭合（`docs/legacy_framework` 中的 7 月确认性报告）。

## 10 月 14 日：复核动摇了"分类"

用更严格的对照重查之后：

- 论文一按单个版本判定结局。在这个口径下，"先就绪后被改坏"有很大一部分是巧合，同口径下的误报率在 45% 到 62%。
- 做支持度匹配后，净的"改坏"只剩 0.2% 到 0.3%，置信区间包含 0。
- 站得住的是另一件事：在字母作答的题上，就绪几乎就等于"发射"。Qwen3-4B 在 L24，Qwen3.5-9B 在 L19。

由此定下第一轮的两个改动：每道题做四个选项置换版本，四个版本一致才算数；把注意力从逐样本的类别转向模型级的发射层。

## 10 月第一轮：答案位置上的发射层与免金标签读出

- **数据**：5 个来源的 5,659 道四选一题，乘四个置换版本，共 22,636 条 prompt。按题组分五折，第 4 折留作锁箱。
- **模型**：Qwen3-4B（base 与后训练版）、Qwen2.5-7B（base 与 instruct）、Llama-3.1-8B。

结论分四条。

1. **发射层是模型级常数。** 被解决的题，自身可解码的中位层在 Qwen3-4B 的三种设置下都是 L24，Qwen2.5-7B 是 L19 到 L20，Llama-3.1-8B 是 L17。它不随题目来源、结局类别、后训练或 prompt 格式变化。发射之前，probe 已能读出答案，但答案不在四个字母的读出方向上。
2. **四类仍在，但严格口径下分布很偏。** 被解决的题约占 15% 到 47%，"改坏"只有 0.3% 到 1.4%，另有近一半到四分之三的题从未被 probe 读出。
3. **读出可以不用金标签。** 用模型自己在四个置换版本上的多数答案当目标训练读出头，逐层准确率与金标签 probe 相差不到 0.6 个点。早退信号由 CSD 的发射跳变等模型内部读数组合而成，组合时训练了一个小逻辑回归，目标是模型自己的满深度输出。所以准确的说法是"免金标签"，不是"免训练"。
4. **干预只能省算力。** 在与满深度输出 99% 一致的要求下，早退平均停在第 25 到 29 层（共 36 层），比只看置信度早 2.4 到 5.4 层，准确率不变，但不能把错题改对。重复中段层只在后训练模型上有不到一个点的收益，没有任何免标签门控胜过"总是 loop"。

## 10 月第二轮：长链生成

在 Qwen3-4B 的思维链生成里逐 token 控制深度。

- **现象仍在。** token 先在隐状态里可得，过几层才写到读出方向上。数字 token 写得最晚，这也解释了剪层为什么特别伤数学。
- **早退在闭环里崩溃。** 自监督的就绪探针 AUROC 有 0.86 到 0.90。但即使退出决定完全不改变发出的 token，正确率也从 66.4% 掉到 27.9%。原因是后面的 token 要读被早退 token 的深层 K/V，免训练的填补方式给出的值模型从没见过。
- **loop 没有深度特异的收益。** 预先指定的主检验降了 3.3 个点，效果与单纯调高温度分不开。

两轮合起来的结论：**判断"何时该少算或多算"能做到，冻结模型执行不了这两个动作。**

## 思路上的五个转变

| | 论文一 | 现在 |
| --- | --- | --- |
| 数据 | 合成代码任务 | 跨域 benchmark，四置换控制字母偏好 |
| 判定口径 | 单版本、事后归类 | 四版本一致，锁箱，诱饵对照 |
| 现象重心 | 逐样本的四类结局 | 模型级的发射层，类别作为样本级补充 |
| 读出 | 金标签 probe | 模型自身共识与内部读数，免金标签 |
| 目标 | 描述现象 | 用读数指导早退和 loop，并确认瓶颈在执行 |

## 下一步（2026-11-11 讨论）

1. **找一个内生的量。** 落在层间残差更新、组件写入或权重空间里，不依赖 probe 和 Patchscope，能逐模型指出发射层，逐样本对上两个节点。目标是一份更扎实的"推理阶段"刻画。
2. **工程底座。** 本分支就是第一步：可复现、可分层抽样、文档分层。下一步是加组件级缓存，并扩展模型面板。
3. **干预。** 先用"加一句提示就能做对"的题定义可救题，验证层级动作本身有没有效，再换成指标门控。动作上借鉴循环模型和训练过的 K/V 方案，例如 LT2 的 KV 回放和 P2N。
