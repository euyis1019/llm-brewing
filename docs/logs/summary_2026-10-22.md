## 0. 一句话结论

- **测量这一侧成立。** 答案和 token 在隐状态里都先"可得"，过几层才"可读"。发射层跨题统一（Qwen3-4B 在 L24，Qwen2.5-7B 在 L19，Llama-3.1-8B 在 L17），在长链生成里也看得到。
- **控制这一侧在冻结模型上基本做不成。**
  - 第一轮（单个答案位置，选择题）：早退省层数、准确率持平，但不能把错题改对。loop 只在后训练模型上有 +0.4 到 +0.9pp 的收益，"何时 loop"的门控没做出来（AUROC 约 0.5）。
  - 生成阶段（CoT）：早退在闭环里崩溃，完美分类器也一样崩，原因是深层 K/V。loop 在 Qwen3-4B 上显著有害，没有发现深度特异的收益。
- **瓶颈在"执行"，不在"判断"。** 分类器能判断谁该少算（AUROC 0.86–0.90），但冻结的模型承受不了早退和 loop 这两种动作。

## 2. 方法定义（页面需要讲清楚的概念）

- **读出方式**
  - **linear probe（"外部可解码"）**：每层在 logit lens 的基础上加一个线性修正，按题组做 5 折交叉拟合，每条样本都拿折外读数。设计说明见 `discussion/1017_linear_probe_设计.md`。
  - **Patchscope / CSD（"自身可解码"）**：把这一层的状态放进只有 "Answer:\n" 的空 prompt，跑完剩下的层，看模型说出哪个字母。
  - **logit lens**
  - **tuned lens**：秩 128，自监督，只在生成阶段使用。
- **可得**：probe 连续 3 层在 4 个版本上都读对。**就绪**：probe 和 Patchscope 在同一段连续 3 层上都读对。最后一层的读数用真实输出代替。
- **题级五类**

  | 类别 | 含义 | A 线 | B 线 |
  |---|---|---|---|
  | R | 就绪，且 4 个版本最终全对 | 47.4% | 32.1% |
  | O | 就绪过，最终丢失 | 1.4% | 0.3% |
  | U | 可得，但一直没就绪 | 4.2% | 8.1% |
  | M | 可得，但一致答错 | 约 0 | 约 0 |
  | NB | 从未可得 | 46.8% | 59.5% |

  6 个配置的区间：R 15–47%，O 0.3–1.4%，U 4–8%，NB 47–77%。
- **发射层**：读出在这一层跳变，答案一次写进 A–D 读出方向。
  - Qwen3 在 L24（落在 ±1 层内的比例：后训练版 67%，base 52%）。Qwen2.5 在 L19，Llama 在 L17。
  - 不同来源、不同类别的发射层都一样。
  - base 模型的尾巴更长：12% 的样本只在末层才定型，后训练版只有 1%。O 集中在这条尾巴上。
- **无监督指标**
  - L0（发射跳变）：只用模型自己的读出和隐状态，组合成停止信号时训练了一个小逻辑回归，目标是"这一层读出已和满深度输出一致"。
  - L1（置换共识读出头）：目标是 4 个版本的多数内容，不用金标签。
  - 更正：报告 v2 第 3.3 节写的"完全不训练"不准确。

**第一轮之后讨论里的补充分析（只用 CPU 复算，写在 S2 对话里，没有落成文件）**
- **O 为什么少（以 B 线为例，逐级收紧条件）**
  - 单版本里"中途 Patchscope 说对、最终答错"有 6094 行。
  - 同样的规则换成某个错误字母，有 11678 行，比正确字母还多。
  - 要求 4 个版本都在某层读对：120 题；再要求连续 3 层：41 题；再要求 probe 也读对：18 题。
  - 结论：单版本口径的 O 大多是巧合。第一篇在 CUE 上的 O 占 14–36%，用的是单版本口径；10-14 的复核显示单版本 O 的误报率是 57–77%。
- **loop 按"loop 之前的结果"分组**

  | 组 | loop 的效果 |
  |---|---|
  | 有对有错 | 6–8% 被巩固成 4/4 全对，安慰剂只有 1–4%，收益集中在这一组 |
  | 全错 | 一道都没有变成全对 |
  | 全对 | 4–11% 被改坏 |

- **发射之后的反转（单版本）**
  - A 线：20% 的版本发射后还会变；其中改对 8.1%，改错 3.4%。
  - Qwen2.5-7B：40% 的版本发射后还会变。
  - GSM 上反转最多（A 线 34%）。

## 5. 为什么效果不好（归因汇总）

| 动作 | 判断这一步（指标/分类器） | 执行这一步 | 根因 |
|---|---|---|---|
| 早退（答案位置） | 可用：99% 一致率下省 6–10 层 | 可执行，后面没有 token 读它的 K/V | 只能省算力，提不了准确率（"假 O"和 O 一起被还原） |
| 早退（CoT） | 可用：AUROC 0.86–0.90，完美分类器也试过 | **失败** | 早退 token 的深层 K/V 是模型没见过的近似，后面所有 token 都要读，误差在长链里累积 |
| loop（答案位置） | **失败**：门控 AUROC 约 0.5 | 后训练模型上小幅有效 | "能救"的 U 只占 4–8%，单次前向识别不出来 |
| loop（CoT） | 晚定门只覆盖了 U 定义的一半（"说不出"，没有"读得出"） | **失败**：作用相当于一次扰动 | 冻结模型没训练过重复跑同一段层；收益与调高温度分不开 |

## 6. 未决问题和已提出的下一步（还没做）

1. **token 级金标准分类**（S2 的建议）：用续写正确率定义 token 级的 R/O/U/NB，先有金标准，再找无监督读出。`rollout.py`、`tokchoice.py` 已经接近这个设计。
2. **无损自投机解码**（S3 的建议）：用就绪分类器决定每个 token 用浅层起草多深，再由满深度并行验证。这样省的是延迟，不是算力。
3. **需要训练的方案**：LayerSkip 式训练、单独的 K/V 补全模块，或 Think-at-Hard 式的 LoRA 加门控做 loop。
4. 指标转作诊断工具：预测哪些题对剪层或量化敏感（目前证据混合）。
5. 在思考模式或更大的模型上复查 loop。原计划里的 Qwen3.5-35B-A3B-Base 已下载在 `/nvme0/if/models/`。
6. CUE 上 O 的对照复核：用单版本"假 O"对照，只需 CPU。
7. S2 里还没拍板的两个设计问题：早停是否只用"全对 + 全错"子集；loop 是否用"有对有错"这一组的 loop 实际结果当标签来找信号。
