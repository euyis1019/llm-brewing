## 0. 构造 benchmark 与冒烟测试（2026-10-16）

**benchmark**（`scripts/build_bench.py`，`data/bench/`）

- 共 5659 题 × 4 个循环置换版本 = 22636 条 prompt：

  | 来源 | 题数 |

  | MATH-MC | 1000（从 4817 道有效题中抽） |

  | MMLU-Pro | 1000（10 选抽成 4 选：保留正确项，固定种子抽 3 个干扰项） |
  | C-Eval | 1340（val 共 1343 道有效题，留 3 道做示例） |

- 5 折按题组划分，并按来源分层。
- 每个来源固定 3 道示例：取题长不超过中位数的题，且 3 道题的正确字母互不相同。

**冒烟测试**（`scripts/smoke.py`）

- token：两个模型在关键位置上 A–D 都是单 token，id 为 32–35，不带前导空格。
- 核心实现校验：

  | 校验 | 结果 |
  |---|---|
  | CSD 的前缀 KV 实现 vs 直接用 hook 做 Patchscope | 各层 argmax 一致率 100%；字母 logit 最大差 0.03–0.5，属于 bf16 噪声 |
  | `forward_sequence` 用不重复的层序列 vs 正常前向 | 差值为 0 |
  | 只重跑最后位置 vs 正常前向 | 最大差 0.06（base）、0.19（instruct） |
  | 左填充批 vs 单条 | 最大差 0.29 / 0.91 logit，bf16 噪声，argmax 不变 |

**A 线 few-shot 的 k**

- 0-shot 的格式遵从率：MATH 和 MMLU-Pro 各 96.5%，其余 100%。
- 1-shot 和 3-shot：5 个来源全部 100%。
- 1-shot 相对 0-shot 的准确率变化：GSM +8.5pp，PythonIO +9pp，MATH +3pp，C-Eval +3pp，MMLU-Pro 持平。
- **决定：统一用 1-shot。** 原规则是"遵从率不低于 95% 的最小 k"，按它会选 0-shot，那样每个来源要丢掉约 3.5% 的样本。改成"所有来源遵从率都达到 100% 的最小 k"，结果是 k=1。

**B 线格式**

- 只给 user 指令（原 chat0）时，Qwen3-4B 在非思考模式下的遵从率：GSM 1.5%、MATH 2%、MMLU-Pro 62%、C-Eval 74.5%，第一个 token 多是 "To"、"We" 这类推理开头。
- 加一句 system 指令（"You are an exam assistant… reply with only the letter…"）后，5 个来源的遵从率全部 100%。
- 在助手位置预填 "Answer:" 时，GSM 上 100% 输出 " **"，不可用。
- **决定：B 线的 chat0 = system 指令 + user（题目和指令），非思考模式。** CSD 的目标 prompt 是同一个 chat 壳（system、指令、助手前缀，含空的 think 块）。
- 这和 PLAN 4.2 有一处偏离：PLAN 规定遵从率低于 90% 就换 Qwen2.5-7B-Instruct。没有换，是为了保住"同结构、只差后训练"这个对比，记录在此。

## 2. probe 训练（2026-10-16 19:57–20:02）

**脚本与设置**（`scripts/train_probe.py`，由 subagent 编写）
- 形式：每层 logit = lens + W·ĥ + b，惩罚 λ‖W‖²，用全批 L-BFGS 求解。实现上做了预条件，是精确的重参数化。
- 交叉拟合：5 折；λ 在内层留出折上选，11 个取值，范围 1 到 1e-5。
- 另训 3 个 null probe：在来源内按题打乱答案。
- 耗时：每条线约 2 分钟。

**校验**
- 顶层 lens 准确率等于真实输出准确率。
- 全部 36 层 full ≥ bias。
- 权重能复现 OOF logit，误差约 5e-6。
- 按 null 自身打乱后的标签算，null 准确率在 0.244–0.26，处于机会水平。
- 按真实答案算，null 在后层约 0.29。这是 lens 锚定项继承下来的，正确的机会水平看"按自身标签"那一行。

  - 不加门控的早退净值为负，或只来自读出头。

  - 一致性最高的层（cons_exit）：B 线比末层投票再多 +0.8pp；A 线比末层投票低 0.9pp。
- ~~这说明"4 版本共识在中层高于末层"是一个近乎完美的、不需要标签的 O 检测器~~。

## 4. depth loop：预先指定的主检验（2026-10-16 20:10 写下，此时还没有看过任何一个 loop_eval 结果）

loop 的复核 agent 确认 `loop.py` 和 `loop_eval.py` 没有 bug，并且用独立实现逐项对过。它提出的几点，按下面的方式处理：
