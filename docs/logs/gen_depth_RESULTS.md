# 生成阶段：用 brewing 指标控制逐 token 深度（迭代日志）

计划与对齐见 `../../discussion/生成阶段_理解确认与计划_2026-10-17.md`。执行窗口从 2026-10-18 03:43 UTC 开始计时（此前会话断线约 10 小时，未计入）。

## 0. 基础设施（03:43–04:10）

**解码引擎**（`scripts/engine.py`）
- 自写前向，复用 HF 权重。KV cache 按 slot 预分配，continuous batching，按层段用 CUDA graph。
- 同一批里每个 token 可以早退、跳层或 loop：
  - 早退的行冻结残差，但继续写 K/V（CALM 状态传播）；
  - loop 只重跑被标记的行，覆写当前位置的 K/V。
- 采样：top-k / top-p 之后做 Gumbel-max，噪声由（题、种子、步、token id）哈希得到。
  - **复核更正**：耦合并不完全。bf16 数值取决于同批的组成，包括注意力长度的分桶和 prefill 怎么分组。所以即使不做任何干预，不同调度下的同一个 job 也会分叉：tfeat_calib 对 base，48 条里有 45 条在 768 token 内分叉，首次分叉中位数约在第 83 个 token。
  - 配对差仍然无偏，只是噪声比设计时假设的大。"分叉率"里包含了这个底噪。
- 正确性校验（`scripts/test_engine.py`）：

  | 校验 | 结果 |
  |---|---|
  | 全序列前向 vs HF | logit 差 0.000 |
  | 贪心解码 vs HF 逐 token argmax | 640/640（CUDA graph 版 639/640，差异是 bf16 近似平局） |
  | graph vs eager | 4/4 条完全一致 |
  | loop 迭代 0 次 vs 不 loop | 384/384 位置一致 |
  | 采样复跑、换 slot 顺序 | 完全一致（但这只测了同一批 job 的顺序，没有改变批组成，见上方更正） |

- 吞吐：微基准（48 条 job，输出上限 384）2130 tok/s，比加 CUDA graph 之前快 2.7 倍。实际运行时基线约 1100 tok/s，带干预约 800–950 tok/s。

**题池**（`data/pool.jsonl`，3044 题）
- GSM8K 1319、MATH-500 500、AIME 24/25/26 各 30、AMC 83、OlympiadBench 582（多答案题剔除 93 道）、Minerva 272、GPQA-Diamond 198。
- 判分用 `scripts/grader.py`（math-verify 加兜底）。

**基线**（Qwen3-4B 非思考模式；T=0.7、top-p 0.8、top-k 20；输出上限 3072 token）
- MATH-500，4 个种子：准确率 83.7%，截断 4.9%，平均 851 token。
- 每题通过率：73% 题 4/4 全对，18.6%（93 题）是前沿题，8.2% 全错。

## 1. 内环：逐 token 深度剖面（teacher-forced 重放，`replay.py`、`analyze_replay.py`；04:10–04:45）

数据：MATH-500 基线种子 0、1，共 1000 条轨迹、84 万 token。逐层计算 logit lens 和"用同一份噪声在该层采样会得到的 token"。重放结果与生成 token 的不一致率为 0.40%（bf16 噪声）。

**1.1 logit lens 下，输出 token 很晚才定下来**
- "该层采样 token 等于末层，并且之后一直相等"的最早层（oracle 早退层）平均是第 30.35 块（共 36 块）。
- 到第 24 层只有 18% 的 token 已定，第 30 层 51%，第 34 层 91%。

| LaTeX 命令 | 4.4% | 31.58 | 37.2% | 0.08 |
| 话语标记（wait/so/but…） | 1.9% | 30.55 | 32.4% | 0.89 |
| 词 | 32.3% | 30.57 | 30.4% | 0.36 |
| 运算符 | 11.4% | 27.34 | 21.2% | 0.14 |

**1.2 静态截断：数字最先坏，对应"剪层伤数学"**

| 数字 token 一致率 | 55.0% | 61.0% | 65.7% | 83.6% |

**1.3 基于 lens 的在线早退规则都不可用**
- 置信度 ≥0.99：一致率 85.9%，平均 31.7 块。每个检查层都要做全词表读出，按开销算比满深度还贵约 2 倍。
- 稳定规则、KL 跳变规则的一致率都 ≤89%。
- 自监督早退探针（`train_exit_probe.py`，从隐状态预测"该层 lens 采样等于末层"）：各层 AUROC 0.86–0.90。
  - τ=0.98：平均 34.6 块，一致率 99.3%；
  - τ=0.95：34.0 块，98.0%。
  - 省下的层很少。

**筛查集**（`data/screen_m500.txt`）：183 题 × 种子 0、1 = 366 条，与基线逐条配对（同题同种子同噪声）。

**统计功效提醒**
- 99% 的轨迹会分叉，中位数在第 26–56 个 token；其中包含批组成造成的 bf16 底噪。分叉之后，结局仍与基线部分相关（复核 2：同种子与跨种子的结局一致率之差，L_c35 是 +3.8pp，T_r084s 是 +7.1pp），并非独立重采样。

## 3. 早退闭环：teacher-forced 一致率高，不代表闭环准确率高

| 配置 | 规则 | 平均执行块数 | 退出率 | Δ准确率 | 修好/弄坏 | 全对题被弄坏 | 截断 | 长度 |
|---|---|---|---|---|---|---|---|---|
| E_t99 | tuned lens 早退探针 τ=0.99（离线一致率 98.4%） | 31.95 | 68% | **−37.2pp** [−43.7, −30.6] | 15/151 | 62% | 27% | ×1.39 |
| X_s31 | 静态截断：全部 token 在第 31 块后退出 | 32.00 | 100% | **−59.3pp** [−65.0, −53.3] | 1/218 | 93% | 75% | ×2.01 |
| E_t999 | tuned lens 早退探针 τ=0.999（最保守） | 34.68 | 44% | **−10.4pp**（相对 A/A）[−16.4, −4.4] | 37/75 | 26% | 15%（A/A 9.3%） | ×1.07 |
| E_l99 | logit lens 早退探针 τ=0.99（多数只跳过最后一块） | 35.03 | 53% | −3.28pp（相对 A/A）[−8.5, +1.6] | 33/45 | 14% | 12.8% | ×1.02 |

- 平均深度相同（32 块）时，按"就绪度"逐 token 分配深度（E_t99）比均匀截断（X_s31）多保住 22pp 准确率（25.96% 对 3.83%），但两者在闭环下都崩溃。
- 最保守的 E_t999 每个 token 平均只省 1.3 块（3.7%），准确率仍然掉 10.4pp，截断率从 9.3% 升到 14.8%。
- E_l99 在 53% 的 token 上跳过最后一块，平均省 1 块（2.7%），准确率 −3.3pp，不显著。
  - 对比第 13 节：让**所有** token 都跳过最后一块（X_s34）是 −47pp。按就绪度只让一半 token 跳过，就避开了绝大部分伤害。这是 brewing 指标"知道哪些 token 可以少算"的最清楚的闭环证据。
  - 但省下的算力只有约 3%。
- **在这个模型上，免训练的逐 token 早退找不到一个"省下可观算力而不掉点"的工作点。**
- 这在闭环层面支持 1.2 节的解释：均匀剪层会打掉晚定型的 token（数字），逐 token 分配能保住其中一部分。

- 被早退的 token，后续层的 K/V 由退出态投影得到（CALM 状态传播）。
- 离线 98.4% 的 token 一致率，闭环下变成崩溃：输出变长、重复，常被截断。这与 Kaplan 2609.14144（60/60 降到 10–28/60）和 2510.22228（剪 1–2 层就崩）一致。
- 推断（复核 2 收窄）：**在免训练的状态传播下，被早退 token 的 K/V 会伤害后续 token。**"深度是共享资源"只是一个假说。还有几种解释没有排除：
  - 没试过别的 K/V 填补方式；
  - 早退探针是在满深度上下文里训练的，在传播的 K/V 下可能失准；
  - 单看 token 通道就有 −17.8pp，而且按每次改变算，早退造成的改变比 loop 造成的伤得多：1.47% 的分歧率伤 17.8pp，2.24% 的分歧率只伤 5.2pp。这更像是早退的错误落在了算出来的数字上（见 1.2 节），而不是一般意义上的累积。
  - E_t99f 并没有陷入重复：闭合重复 16-gram 的 token 占 4.8%，A/A 是 5.0%。
- **诊断实验 E_t99f**（05:36）：退出决策和发出的 token 不变，深层 K/V 按满深度计算（不省算力，只为拆分来源）。

  | 配置 | 相对 A/A 的 Δ | 95% CI | 修好/弄坏 | 长度 |
  |---|---|---|---|---|
  | E_t99（K/V 状态传播） | −40.4pp | [−47.5, −33.6] | 14/162 | ×1.41 |
  | E_t99f（满深度 K/V） | **−17.8pp** | [−23.8, −11.8] | 24/89 | ×1.11 |

  - 稳健的结论：把 K/V 换成满深度，能找回 22.7pp [16.1, 29.2]。剩下的 −17.8pp 与早发出的 token 一起出现。
  - **复核 2 更正**："一半经 K/V、一半经 token"这种拆分不可识别：
    - 四格设计缺一格（满深度 token 加传播的 K/V）；
    - 两个通道有很强的交互：在共享前缀上，传播 K/V 使逐 token 分歧率从 1.47% 升到 5.89%，底噪是 0.58%；
    - E_t99f 的退出也不是"完全相同"：退出率 66.4% 对 68.1%，平均块数 32.2 对 31.95，轨迹也不同。
  - 两个通道都不安全，这一点成立。这与单 token 选择题不同：选择题只有一个答案位置，没有后续 token 读它的 K/V。

## 4. loop 在做什么：与后训练方向的对齐检验（`loop_delta.py`，04:52–05:02）

**设计**
- 在 1517 个 teacher-forced 位置上，用 instruct 模型自然分布的 top-32 id，比较两个变化：
  - loop 引起的对数概率变化；
  - 后训练引起的变化（Qwen3-4B 减 Qwen3-4B-Base，同一前缀）。
- 先在 32 个 id 上重新归一化并中心化，再算余弦。
- 零假设：打乱位置配对后的余弦。

| 窗口 | 全部位置余弦（零假设） | 数字 | 分叉词 | 高熵 | 晚定 | 自然 top-1 的 Δlogp | 最大 \|Δ\| 中位数 |
|---|---|---|---|---|---|---|---|
| 18–25（brewing） | −0.023（+0.020） | +0.116（+0.092） | −0.098（−0.010） | −0.117（−0.032） | −0.031（+0.028） | −0.061 | 2.3 |
| 24–31 | −0.129（−0.038） | −0.218 | −0.024 | −0.096 | −0.130 | −0.104 | 3.2 |
| 28–33（晚段） | −0.243（−0.120） | −0.546（−0.256） | −0.011 | −0.051 | −0.263 | −0.073 | 3.1 |
| 18–25 阻尼 | −0.013（+0.016） | −0.021 | +0.055 | −0.028 | −0.058 | −0.007 | 0.55 |

**复核更正（06:10）：上表的余弦大部分是在测"锐化/压平"这条轴**
- 后训练方向本身主要就是锐化：cos(自然分布, 后训练变化) = +0.51，数字上是 +0.77。纯温度变化的余弦恰好是 −0.51。
- 所以要先去掉沿自然 log-prob 方向的分量，再看 loop 和后训练是否同向。零假设改为同类别内 200 次置换。

| 窗口 | 熵变化（nats） | top-1 改变率 | KL(自然‖loop) | 去掉锐化轴后的余弦 | 置换零假设 |
|---|---|---|---|---|---|
| 18–25 | −0.015 | 10.7% | 0.067 | **−0.064** | +0.003±0.004 |
| 24–31 | −0.080 | 15.2% | 0.123 | −0.046 | +0.000±0.005 |
| 28–33 | −0.063 | 13.8% | 0.089 | −0.040 | −0.005±0.005 |
| 18–25 阻尼 | −0.004 | 2.7% | 0.006 | −0.033 | −0.001±0.005 |

分类别看：
- 18–25 窗口：分叉词、高熵、晚定、随机位置都是 −0.06 到 −0.09，零假设约 0±0.01。
- 28–33 窗口：在分叉词和高熵位置略为正（+0.045、+0.012）。
- top-1 改变率：高熵位置 25–35%，晚定位置 14–25%，数字约 0.3%。

**修正后的结论**
- loop 不是在压平分布，而是在**重新排序**：把概率从自然 top-1 挪到另一个候选上，同时略微变锐（不确定的位置熵降 0.15–0.18 nats）。
- 去掉锐化轴后，**所有窗口都与后训练方向轻微反向**：18–25 是 −0.064 [−0.079, −0.050]，24–31 是 −0.046，28–33 是 −0.040，连几乎不改分布的阻尼版也是 −0.033。零假设约为 0±0.005。
  - 这种反向是通用的，不专属 brewing 窗口：随机位置也有 −0.086。
  - 窗口之间的排序还会随候选集大小翻转：用 top-16 时 18–25 是 −0.019、28–33 是 −0.052；用 top-8 时分别是 −0.051、−0.060。
  - 熵降 0.15–0.18 nats 只出现在 24–31 和 28–33；18–25 在分叉词和高熵位置只降 0.02–0.05。
- 复核 2 更正：先前"这与闭环结果对得上"的说法不稳健，已撤回。
- 第一轮里"loop 只对后训练模型有用"在这里得不到"loop 放大后训练"的支持。

## 5. A/A 对照：筛查里的"增益"来自均值回归（05:25）

- AA_salt1：同一基线策略，换一份采样噪声，题和种子标签不变。
- 它相对原基线也有 **+3.28pp** [−1.64, +8.20]（修好/弄坏 47/35）。这就是筛查集选择偏差的大小。

## 16. "完美分类器"早退：只有 K/V 通道（2026-10-19）

**用户的问题**：早退或 loop 不成立，是不是因为缺一个用 hidden state 训练出来的 per-token 分类器？

**设计**（`oracle` 策略）
- 先完整跑一遍满深度，再事后给每个 token 找最早的一层：从这一层起，所有列出的层（16, 18, …, 34）的读出，用同一份噪声采样都已等于满深度的 token。
- 发出的 token 就是满深度的 token，token 层面零误差。只把这个 token 在退出层以上的 K/V 换成退出态的投影（CALM 状态传播）。
- 这相当于一个不会犯错的退出分类器，同时也补上了复核 2 指出缺的那一格：满深度的 token，加上传播的 K/V。

| 配置 | 退出率 | 平均执行块数 | 准确率 | 相对 A/A | 截断率 | 写完时的准确率 |
|---|---|---|---|---|---|---|
| A/A | — | 36 | 66.4% | — | 9.3% | 73.2% |
| O_logit（完美分类器，logit lens 判定） | 90.0% | 30.51 | 27.9% | **−38.5pp** [−45.4, −32.0] | 21.3% | 35.4% |
| O_tuned（完美分类器，tuned lens 判定，退得更早） | 92.5% | 25.11 | 9.8% | **−56.6pp** [−63.4, −50.0] | 62.3% | 25.4% |
| E_t99（真实探针，K/V 传播） | 68.1% | 31.95 | 26.0% | −40.4pp | 26.8% | 35.4% |
| E_t99f（真实探针，满深度 K/V） | 66.4% | 32.2 | 48.6% | −17.8pp | 16.7% | 58.4% |

**结论**
- 分类器完全不犯错时，只要被退出 token 的深层 K/V 用退出态去补，准确率就从 66% 掉到 28%。这几乎和真实探针一样（26%）。
- 退得越早（平均 25 块，省约 30%），崩得越厉害（10%）。
- **瓶颈不在"判断"，而在冻结模型上执行早退这个"动作"。** 不管分类器训得多好，免训练的 K/V 填补都会让长链崩溃。
- 要让早退可用，得让模型或 K/V 补全模块经过训练，或者改用自投机验证（满深度验证会把 K/V 修正回来）。
